# Leader Realm (Tera) — Ages 17+

This final stage is **cloud-first** and is intended for older learners ready for computationally serious AI work. Students rent GPU compute, train and fine-tune their own models, and deploy them as services that the robots they built at earlier realms can call. Linux, CPython and the vision pipeline are already familiar from the Engineer realm, so the new material is scale and the engineering that comes with it: GPU acceleration, dataset and experiment management, reproducible environments, deployment, and the cost and energy budget of every training run. It is also where **C++** enters the program: once a pipeline has to hold a frame rate on a device with a fixed power budget, students profile their Python, find the loop that costs them and rewrite it in C++. Students who want their intelligence to live on the robot itself can additionally buy a **Jetson Orin** and implement the same concepts on an edge device; the purchase is optional and the realm is designed to be completed in full without it. This stage supports ambitious capstones, research-style projects and competition pathways.

## Cloud-First by Default, Edge by Choice

The default path at this realm is rented cloud GPU compute, for four reasons. It removes the hardware barrier entirely at the most expensive point in the program, so no student is priced out of the final realm. It gives learners access to machines far beyond anything a hobby board can do, which is what makes training a model of their own realistic rather than a demonstration. It teaches the workflow the industry actually uses — provision, containerize, train, evaluate, deploy, tear down — with reproducibility and version control as habits rather than lectures. And it makes cost and energy visible: a student who watches a training run accumulate charges and kilowatt-hours understands the environmental argument in the AI literacy frameworks in a way no reading assignment achieves.

As at the Engineer realm, accounts and billing sit with ByteBear: instructor-created accounts, hard spending caps, auto-shutdown on idle instances and no student holding raw cloud credentials.

**The optional edge path** is a **Jetson Orin Nano developer kit**, bought by the student who wants the intelligence to live on the robot rather than in a data centre. It runs the same concepts under different constraints — a fixed memory ceiling, a power and thermal budget, a model that must be converted and optimized before it will fit, and no network dependency at all. Students on this path do not learn different material; they implement the same model twice and can argue from their own measurements about where inference belongs.

**Where C++ enters.** Students have written Python for four realms, and the argument for a second language should be earned rather than asserted. It is earned here: a vision pipeline that must hold a frame rate inside a fixed power and memory budget is the first problem in the program where Python's convenience actually costs something measurable. Students profile their own pipeline, find the loop responsible, reimplement it in C++ against the runtime's C++ API, and measure the result. The point is as much about method as about syntax — that you profile before you optimize, and that you report the frame rate and memory you measured rather than the improvement you expected. This work is not reserved for the edge path; a cloud-path student profiles and optimizes the same pipeline on their instance, and both paths meet the same C++ material.

That comparison is worth more than either deployment alone, so cloud-path students should not miss it: ByteBear should keep at least one shared Orin available for remote access, letting every capstone report real edge numbers even when only some students own the hardware. Buying an Orin is never a requirement for completing the realm, the capstone or the showcase.
